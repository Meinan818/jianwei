# 接手提示词（复制粘贴用）

> 换班时，把对应那一段**整段复制**，贴给另一个 AI 的对话框。
> 不用改任何字——两个 AI 会自己读文件、自己判断该不该开工。

---

## 一、贴给 Claude 的

```
你接手「简味点单 / 饭否外卖」这个项目。先别动任何文件，按下面顺序做：

1. 完整读仓库根目录的 AGENTS.md（这是唯一权威交接文档，尤其第 0 节「多 AI 协同开发协议」）。
2. 读 .workbuddy/coop/state.json，看 holder 是谁。
3. 读 .workbuddy/coop/BATON.md 最后两条记录，了解上一个 AI 干了什么、留下什么。
4. 跑 git status 和 git log --oneline -5，确认当前分支、未提交改动、有没有未推送的提交。

然后向我汇报（只汇报，不要改代码）：
- 现在轮值锁在谁手上？我（Claude）现在能不能开工？
- 当前分支是什么？有没有未提交/未推送的东西？
- 上一个 AI 留下的、需要我接着做的事是什么？
- 你建议我第一步做什么？

汇报末尾必须按 AGENTS.md §0.5 的格式给出「—— 下一步 ——」区块，告诉我该去找谁。

注意：你的分工是「方案设计、架构判断、代码审查」。如果手里是「按既定方案写代码」这类活，
可以直接建议交给 Codex 执行，你负责审查它的产出。
```

## 三、第一次启用时，先用这一段（收尾专用）

> 现在的仓库状态是「会员功能在分支上没合回 main」，**协同开始前必须先收尾**。
> 用下面这段让正在轮值的 AI 先把仓库弄干净。

```
先读仓库根目录 AGENTS.md 的第 0 节「多 AI 协同开发协议」和第 1.1 节「进度快照」，

当前情况：我们在 codex/membership-pending-sql 分支上，会员功能（第十六版）已通过本地验收，
但这个分支还没合回 main，另有 5 个文件未提交（AGENTS.md、CODEX_HANDOFF.md、docs/交接说明.md、
scripts/e2e-membership.html、src/data/app-meta.ts）。

请先向我汇报（不要动任何文件和 git）：
1. 这 5 个未提交文件分别是什么改动，要不要一起提交？
2. 会员功能现在是否达到「可以合回 main」的标准？对照 AGENTS.md §8.1 的验证要求逐条说明。
```

## 四、忘词了怎么办

不用回来翻这个文件。**直接跟当前那个 AI 说：**

```
看一下 AGENTS.md 第 0 节，告诉我现在该找谁、把哪段提示词贴过去。
```

它会读规则、读轮值锁，然后告诉你答案。
