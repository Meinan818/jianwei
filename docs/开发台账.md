**过程中的两个坑（已解决）**

1. **git 推不上 GitHub**：报 `schannel: failed to receive handshake, SSL/TLS connection failed`。
   根因：本机开着 FlClash（`127.0.0.1:7890`）且系统代理已启用，但 **git 不读 Windows 系统代理**，走直连在国内时通时断。
   解决：`git config --global http.https://github.com.proxy http://127.0.0.1:7890`（仅对 github.com 生效）。
   效果：直连 50 秒 → 走代理 3 秒。副作用：**FlClash 关闭时 git 连不上 GitHub，需提醒用户开启。**
2. **Cloudflare 构建配置**：出现 "Configure your Worker project" 说明点进了 Workers 分支，需回到 `Workers & Pages → Create application → Pages → Connect to Git`。
   实际填写的值：Build command `npm run build:standalone`、Build output directory `dist/client`、Framework preset `None`、Production branch `main`、环境变量留空。
   `Protect with Cloudflare Access` 必须保持关闭，否则会给演示站加登录墙。

### 2026-09-27 · 演示保障：接单超时放宽到 8 分钟

**起因**：用户决定按"先修演示隐患 → 接 Supabase → 做精 1–2 个亮点功能 → 补作品集文档"的顺序推进。

**调研纠正**（原先的判断有误，记录备查）：商家接单超时**不会自动拒单**，订单保持 `pending` 只打 `acceptExpired` 标记；
顾客端显示的是**黄色**提示条而非红色报错；两个清理函数只在进入订单列表 / 收银台时各跑一次，不是定时轮询。
真正会自动执行的只有待支付 15 分钟自动取消。

**改动**：`MERCHANT_ACCEPT_TIMEOUT_MS` 由 3 分钟放宽为 8 分钟（`src/hooks/useOrders.ts`），
避免现场演示切端讲解时误触发提示条。要专门演示"超时提醒"时把常量临时改成 `20 * 1000`。
`AGENTS.md` §4.3 的超时规则同步补全为"常量位置 + 两种超时的实际行为"。

**验证**：`npx tsc -p tsconfig.app.json` 0 错误；`npm run build:standalone` 通过。
